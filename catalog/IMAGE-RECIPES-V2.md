# Image install recipes: source-derived, unverified

Eight owned models now have executable image recipes (19 runnable variants). All new or replaced recipes have `verified.status: unverified`, `benchmarked: false`, and no measured speed claim. No dependencies were installed, model weights downloaded, third-party code imported/executed, GPU allocated, or production endpoint called during preparation.

The recipes require the runtime extension implementing checksum-verified `install.support_files`, `{support_dir}`, and `install.venv.lockfile`. The correct code placeholder is `{code:<dest>}`. A secondary weight destination is relative to `{weights}`: `dest: adapter` means `{weights}/adapter`, not `{weights}/weights/adapter`.

Native bridges bind only to 127.0.0.1 and serialize requests. Gateway calls use `/v1/systemone` for text and `/v1/multimodal` for images; Imajev and AutoJev route both to the existing author `/v1/systemone`. Wrappers never retrieve URLs or caller-supplied local image paths. Offline environment variables are supplied by the installer. All weights and source revisions are immutable and checksum-verified before launch.

## Native bridge modifications and limits

- Jev-Omni's reference loader calls `snapshot_download` on both checkpoint and Gemma base. Our wrapper instead uses the separately verified local paths, imports the pinned loaders and performs the same backbone replacement. CPU-first assembly is the documented BH accommodation. A counting processor delegates the exact native call unchanged and records actual processed input length; no token estimate is returned. Native output tokens are zero. Noul maps `[no, yes]`, choice maps criteria order, score maps level order; the rubric follows BH's options-only bridge. Native results remain under `native`, with confidence untouched. Duplicate option descriptions are rejected because the author's probability dictionary would collapse them. One image only; audio/video are outside this recipe.
- JPT's executable NVIDIA path is HF, not its former vLLM serving suggestion. No vendor extension or undocumented endpoint is required. Reflex portable recipes use CPU BF16/MPS FP16 and reference kernels. Imajev does not enable merge-LoRA, fast CUDA graphs or thinking. Exact published runtime/latency equivalence is unverified for every route.
- NeoHorse's benchmark weight pin `56c36ae625a3ccca47d9a34fb7ca6203b39b309e` remains unresolved. `weights.benchmark_revision` retains it, while actual install metadata uses official same-author `434cb21d3a994a953d3ae5788405fcb2c4970554`, with the previously independently hashed full files. Every runnable NeoHorse variant is `benchmarked: false`; no published weight equivalence is claimed. The existing GGUF variants still have no install recipe: building their CUDA runtime needs a separate reviewed build extension.
- CPU/MPS memory, operator compatibility, package installation, readiness and numerical parity have not been measured. Frozen GPU author locks can include training dependencies and require substantial installation disk. No runtime package/weight download was run here.

## Integration review required

The baseline gateway's `_check_distribution` divides author probabilities by their sum; it can modify four-decimal Jevify outputs. Its choice check also imposes a first-option tie after rounded probabilities, which can reject the author's unrounded winner. **The lead must reconcile this gateway behavior before claiming end-to-end preservation of author probabilities.** These recipes/wrappers preserve native outputs and do not compensate with invented confidence or recalibration. Runtime extensions must be merged before these support-file/lock recipes execute.

## Validation performed

- `python3 -m unittest tests.test_catalog_recommend tests.test_recipe_runtime`: 21 tests passed on the worker baseline.
- All eight model JSONs passed catalog validation. All 19 runnable recipes passed support checksum writing, Python `compile` without imports, concrete dry-run command expansion and environment placeholder expansion against the runtime-extension worker's checkout. Frozen recipes generated `uv sync --frozen`; direct routes generated pinned `uv pip install`. No execution command was launched.
- Four inert-stub checks exercised Jevify, JPT, Reflex and NeoHorse wrapper transports and verified unchanged native probabilities, non-max confidence and usage. Native modules were replaced with inert test stubs; no third-party code was executed.

Catalog variant IDs are retained as stable identifiers: JPT `bf16-vllm-llm2jev` and Shisa `bf16-vllm` now install the native PyTorch routes described above; their `runtime`/`runtime_version` fields describe the executable backend. This does not claim vLLM execution. Existing `image_input` author/benchmark provenance is retained alongside explicit `installer_transport` and `installer_limits`.
