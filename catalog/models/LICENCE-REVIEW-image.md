## Open questions (need an answer from the author or the lead)

1. **NeoHorse-Jev-4B revision.** The BH pin `56c36ae6` is not in the HF commit history (only `b50e043`, 25 Sep, and `434cb21`, 28 Sep, exist). All weight LFS oids are identical at `b50e043` and `434cb21`; only README and SHA256SUMS changed. The file list is from `434cb21`. Ask the author whether `56c36ae` has the same weights.
2. **Jevify licence string.** The card says `gemma`, the base card and Google's Gemma 4 licence page say Apache-2.0. Confirm which terms the author intends before a commercial installer ships.
3. **AutoJev weights access.** The card says "While the weights are private, authenticate". The HF API reports `gated: false` and public tree access worked at `6f5b557e`. Confirm public access.
4. **Imajev-4B server pin.** `mohit67890/imajev@8501f5c3` (ROSTER "server") is a GitHub commit. The HF repo `mohit67890/imajev` returns 401 (not public). The intake vendor copy is GitHub `4469df3c`. Confirm which code the author serves.
5. **Jev-Omni training data.** The card has no training-data section, only "nothing in it was trained on Jev output". Its evaluation dataset `akhilaaa3/decision-bench` says its scenarios were generated with Claude Opus 5. Check Anthropic terms if any of that data was used in training.
6. **Reflex-4B configuration.** The ImageJev row uses the frozen `stable` configuration (no adapter). The JevBench text recipe uses LoRA `kshetrajna12/reflex-qwen3.5-4b-lora@9df1cbbb`. The JSON records the stable one. Confirm that the two rows are meant to differ.
7. **Base revisions not pinned by the card.** Jevify and Shisa do not name the Gemma 4 26B-A4B-it revision they were trained from. The HEAD revision `4d7ae498` was read, but it may not be the one used.
8. **Non-benchmarked variants not added.** Same-author conversions exist: `TokenRhythm/NeoHorse-Jev-4B-GGUF` and the imajev MLX adapter in `mohit67890/imajev-4b/mlx/`. Neither has a verified readout path, and the imajev MLX base conversion was not identified. Not listed as variants.
9. **Brief ranks vs official ranks.** The brief's `capability_rank` values follow the brief's numbering. The official ImageJev v0.3 ranks are in each JSON as `official_rank_in_v0.3_ranking`, and they differ (e.g. autojev official 11, vjev 29). Imajev-9B (official 5) and JPT-9B (official 8) are in the v0.3 ranking but not in the brief's list.
